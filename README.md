# 초등방과후 프로그램 운영 관리 (hoseo_ops)

호서대학교 앵커늘봄총괄센터·AI·SW교육센터의 학교·기관 접수, 강사 모집·배치, 운영 목록, 운영 통계, **강사서류**(서류 작성·발송·증명서)를 한곳에서 다루는 시스템이다.
강사서류 작성 프로그램은 예전 저장소 hoseo_docs에서 이 저장소의 `docs/`로 옮겼다(2026-11-21).

화면 주소(메인 페이지): https://hoseoican.github.io/hoseo_ops/ — 주소만 열면 메인에서 운영 관리·강사서류·강사·보조강사·기관 담당자 화면을 고른다. 아래 `?` 주소는 예전 그대로 `app.html`로 넘어간다.

| 화면 | 주소 |
|---|---|
| 운영(관리자) | `?a=운영자키` + 로그인 |
| 주강사 수업 신청 | `?r=teacher` (예전 `?b=vac`만 있는 주소도 동작) · 사업 `&b=vac` |
| 보조강사 수업 신청 | `?r=asst` |
| 기관 담당자 페이지 | `?join=1` |
| 기관 전용 화면 | `?s=학교토큰` (관리자 미리보기 `?s=PV-…`) |
| 타대학 희망 강사 선택 | `?u=토큰` |
| 통계 공유(보기 전용) | `?st=토큰` |
| 운영 화면에서 바로 강사서류 | `?a=운영자키&v=docs` |
| 강사서류만 따로 | `docs/` |
| 강사 서류 제출(개인 링크) | `docs/apply.html?t=…` |

## 구조
- 화면: `index.html`(메인 페이지, `src/portal.html`) + `app.html`(운영 관리 화면 전체, 빌드 결과 — 직접 고치지 않는다). 주소에 `?`가 붙어 있으면 `index.html`이 `app.html`로 그대로 넘긴다. 메인의 「운영 관리」 카드는 `app.html?admin`(접속 구분 + 비밀번호 로그인 화면)으로 간다. 운영자 링크(`?a=`)도 그대로 되고, 비밀번호를 처음 정할 때만 필요하다.
- 서버: 구글 앱스 스크립트 웹앱 하나(공유드라이브). **`Code.gs`와 `appsscript.json`만 있고 HTML 파일은 없다.** 데이터는 구글 시트(스크립트 속성 `SSID`)와 연도별 파일(`Y_…`).
- 연결: 화면이 웹앱 주소로 `{ fn, args }`를 POST(text/plain) → `doPost`가 허용 목록(`RPC_FNS_`)에 있는 함수만 실행해 `{ ok, r }` 또는 `{ ok:false, error }`를 돌려준다. 웹앱 주소는 `config.js`의 `OPS_API`.
- 웹앱 주소로 직접 들어오면(`doGet`) 같은 물음표 값을 붙여 이 화면으로 안내한다. 학교·강사·관리자에게 나가는 링크는 모두 이 화면 주소(`Code.gs`의 `PAGES_URL_`)로 만든다.
- `Code.gs`는 이 저장소에 올리지 않는다(강사서류 저장소와 같은 방식).

## 원본과 빌드 (`src/`)
```
python3 src/build.py      # → app.html, index.html
```
- `src2.html` 화면 원본(화면 로직·디자인) → `to_gas.py`(`data.json` 필요)가 화면 코드·디자인으로 나눈다.
- `App.html` 껍데기(로그인·저장·서버 연결), `shim.html` 주소 읽기·서버 호출(fetch) 바꿔 끼우기.
- 화면 코드에 `//` 문자열을 쓰지 않는다(정규식은 `[/][/]`). 템플릿 문자열 안에 `<?`, `?>` 금지.
- 버전: `App.html`의 `APP_VER`, `src2.html`의 `LIB_VER`를 함께 올린다(운영 화면 오른쪽 위에 보임).

## 서버 배포 (공유드라이브)
1. 공유드라이브 → 새로 만들기 → 더보기 → Google Apps Script. 파일은 `Code.gs`, `appsscript.json`(편집기 「프로젝트 설정 → appsscript.json 표시」) 두 개.
2. 프로젝트 설정 → 스크립트 속성: 예전 프로젝트의 `SSID`, `ADMIN_LINK_KEY`, `ADMIN_PW_HASH`, `ADMIN_PW_SALT`, `ADMINS`, `Y_`로 시작하는 것 전부, `PLAN_FOLDER`, `LEGACY_S`를 그대로 옮긴다.
3. 배포 → 새 배포 → 웹 앱: 실행 계정 「나」, 액세스 「모든 사용자」. 권한 승인.
4. 웹앱 주소(…/exec)를 `config.js`에 넣는다.
5. 코드를 고친 뒤에는 `교체 → 저장 → 배포 관리 → 연필 → 「새 버전」 → 배포` (새 배포는 주소가 바뀌므로 쓰지 않는다).

## 강사서류 (`docs/`)
- 강사서류 작성 프로그램 전체(`docs/index.html`, 강사 제출 화면 `docs/apply.html`, 서류 양식·증명서 스크립트). 자세한 내용은 `docs/README.md`.
- 운영 화면 맨 위 메뉴 「9 강사서류」를 누르면 머리글 아래가 강사서류 화면으로 바뀐다(같은 주소의 틀 안, 로고 머리글은 숨김). 다른 메뉴로 갔다 와도 작업하던 화면이 그대로 남는다. 대학별 관리자에게는 보이지 않는다.
- 강사서류는 처음 열 때 **운영 관리 관리자 계정**(접속 구분 · 관리자 · 비밀번호)으로 로그인한다. 운영 관리 서버 `docsLogin`이 확인 후 강사서류 접근 코드(운영 관리 스크립트 속성 `DOCS_CODE`)를 넘겨주고, 구글 시트 연동과 「강사 자료 공유」가 켜진다. 고친 사람 이름 = 로그인한 관리자(총괄은 이름 입력). 「이 브라우저에 기억하기」를 끄면 그 탭에서만 유지. 「9 강사서류」 안에서는 운영 관리 로그인(`docsCode`)으로 바로 열린다. 빈 강사((이름 없음))는 자동으로 만들지 않는다.
- 따로 열면(`docs/`) 예전처럼 혼자 동작하고, 왼쪽 메뉴 「← 운영 관리」로 돌아간다(`app.html?admin&v=docs`로 이동).
- 강사서류 자료는 브라우저(IndexedDB `anchor-lecturer-docs`)와 강사서류 앱스 스크립트(구글 시트·드라이브)에 있고, 주소 체계(hoseoican.github.io)가 같아 옮긴 뒤에도 그대로 이어진다.
- 운영 통계 「자료 올리기 → 강사서류 운영현황 시트 불러오기」: 강사서류 「운영현황」에 등록한 구글 시트를 같이 쓴다. 시트 등록·삭제는 강사서류에서만.
- 예전 주소 hoseoican.github.io/hoseo_docs/ 는 새 주소로 넘기는 안내만 남겼다(제출 링크 `apply.html?t=` 포함).

## 강사 명단 · 강사 화면 연결 (3단계)
- 강사서류 「운영 관리에서」: 운영 관리 강사 명단에서 골라 이름·연락처·이메일·주강사/보조강사를 채워 등록(한 방향). 「9 강사서류」 안에서는 운영 관리가 이미 받은 명단을 바로 씀, 따로 열면 `docsInstList`(DOCS_CODE 확인).
- 강사 수업 신청 화면 「서류 제출」: 운영 관리 서버 `teacherDocsTicket`이 HMAC 확인증(6시간)을 만들고, 강사서류 서버 `lsso`가 그 강사의 유효한 제출 링크를 찾아 `docs/apply.html?t=…#sso=…`로 연다(본인 확인 생략). 서명 키 = DOCS_CODE = 강사서류 ACCESS_CODE.
- 운영현황 시트는 현행 유지(자동 기록 없음).
- 강사 화면 속도: `teacherSession_`이 강사 기록을 캐시(`ti_<id>`, 10분, 명단 저장 시 `instv`로 무효화).
